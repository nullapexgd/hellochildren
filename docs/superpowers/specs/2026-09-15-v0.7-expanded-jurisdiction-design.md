# On Your Processor v0.7 — Expanded Jurisdiction Edition

## Status

Approved in conversation on 2026-09-15. This document defines the manuscript architecture for v0.7. It is the binding design for the implementation plan that follows.

## Purpose

v0.6 proves that authority inside a modern Mac has a jurisdiction. v0.7 makes that thesis feel structural rather than anecdotal by following several operations farther sideways: from paths to storage, from addresses to mappings, from application requests to hardware, and from waiting to the event that ends the wait.

The expansion must add genuinely different boundaries. It must not inflate the existing manuscript by explaining “root is not omnipotent” eleven more times.

The target is a serious small technical book that remains readable as comedy:

- enough distinct examples that the thesis is no longer one clever observation;
- enough evidence that technical readers can trust the boundaries;
- enough dialogue that non-experts keep moving;
- enough structure that every chapter adds a new noun to authority.

The directional length target is 42,000–48,000 words. Coverage and pace outrank the number. Missing a jurisdiction blocks release; missing a word target does not justify padding.

## Non-negotiable editorial rule

The existing evidence rule remains unchanged:

> If proven, say it. If inferred, label it. If an undocumented Apple string exists, quote it without inventing semantics.

Characters may be unhinged. Architecture may not be casually fabricated to support them.

Comic absolutes may appear as titles or dialogue, but nearby prose must establish their scope once, briefly. The prose must not explain the joke a second time.

## New chapter contracts

### 14. Your File Does Not Exist

Owns the distinction among pathname, directory entry, filesystem object, vnode-level representation where supportable, open file description or descriptor, unlinking, mounted view, and snapshot-relative existence.

It must show that a name can disappear while an already-open object remains usable, and that “the file” depends on which namespace and filesystem state the speaker means. It must not repeat the System/Data volume or Signed System Volume lesson from Chapter 13.

Protected exchange:

```text
XNU:
read /Users/efeali/book.txt.

SSD:
what's a Users

XNU:
...

SSD:
what's a file
```

### 15. Please Wait, I’m Writing

Owns the distinction among an application accepting Save, a write call accepting bytes, close, filesystem bookkeeping or commit, controller completion, and the narrower claim of surviving power loss.

`write()` success, `close()`, sync operations, filesystem consistency, controller completion, and persistence must not become synonyms. Apple-specific sync behavior may be included only with precise receipts and scoped language.

The chapter pays off later when shutdown warns that a clean process exit does not certify every related write.

### 16. Everybody Has an Address

Owns virtual addresses, physical addresses, device-visible or I/O virtual addresses, and memory-mapped I/O. Identical-looking numbers can name locations in different maps.

It must not confuse memory addresses with WindowServer coordinates, bootstrap namespaces, URLs, IP addresses, or other uses of “address.” Those may appear only as a short joke about overloaded vocabulary.

### 17. That Is Not Your Memory

Owns reservation, backing, residency, page faults, sharing, copy-on-write, and compression at an explanatory level appropriate to this book.

“Unified memory” means an integrated physical-memory architecture. It does not mean every actor receives communal access. Allocation, accessibility, residency, and ownership remain separate claims.

### 18. Memory Has Borders

The existing chapter is refocused on enforcement: MMU permissions and translation, DART/IOMMU mappings for device DMA, and memory-controller arbitration. It receives the loading-dock and Thunderbolt material only where it directly demonstrates an enforced border.

The bouncers enforce mappings without knowing why Safari wanted the bytes.

Protected lines remain:

- “Policy without enforcement is a wish. Enforcement without policy is a very fast misunderstanding.”
- “The DRAM cells store charge and have never heard of root.”
- “A cable should not be a constitutional amendment.”
- `DART: absolutely fucking not.`

### 19. The Cache Has Receipts

Owns cache taxonomy, locality, visibility, coherence, invalidation, and writeback. It distinguishes CPU caches from trust caches, page or buffer caches, browser caches, and network caches.

Cache coherence is not authorization and is not a durability guarantee. The title must not imply that an Apple trust cache stores execution history, provenance, or literal receipts.

### 20. You Never Talked to the Hardware

Follows an ordinary operation through a defensible subset of APIs, system calls or IPC, kernel or userspace drivers, queues, buses, firmware, and devices.

The title is a scoped comic exaggeration. Direct mechanisms exist, and the chapter must not claim that every operation follows one universal path. Its purpose is to show delegated authority and how every layer takes credit for the same outcome.

### 21. The Firmware Nobody Invited

Owns the existence of code that launchd never launched and XNU does not manage as an ordinary process. It distinguishes boot firmware, device or controller firmware, and software executing on peripheral or independently booted processors without inventing one universal firmware layer or private ABI.

Protected exchange:

```text
launchd:
I manage userspace.

firmware:
cool.

launchd:
what's your PID

firmware:
my what
```

### 22. The Network Does Not Care About Your Process

Follows a useful path from socket through protocol stack, interface selection, driver, controller, PHY, and network.

A local PID does not inherently travel in a packet. The chapter must also say that local policy can attribute sockets and that application identity can be carried explicitly by higher-level protocols. “The network does not care” is the joke, not a universal impossibility claim.

### 23. The CPU Is Waiting

Separates runnable, blocked, spinning, scheduler-idle, pipeline-stalled, and memory-stalled states. “Waiting” needs a subject, object, and mechanism.

Network I/O supplies a concrete reason for a thread to wait. This chapter must not treat all waiting as scheduler sleep.

### 24. Who Woke Me Up?

Separates I/O completion, timers, wait queues, service demand, and whole-machine wake. It asks which object resumed and which event made it eligible.

This chapter deliberately does not teach hardware interrupt taxonomy. It prepares that distinction and leaves the full delivery question for Chapter 31.

### 31. Please Stop Interrupting Me

This is a short coda, approximately 900–1,200 words. It begins from Spacetime’s exact final `zzz` in Chapter 30 and asks what, exactly, would end that sleep.

It distinguishes synchronous exceptions or traps, hardware interrupts, Mach exceptions, Unix signals, routing, and deferred work. It explicitly separates “an interrupt was delivered” from “a thread woke,” “a service launched,” and “the machine woke from sleep.”

The chapter ends at the question of who owns delivery when the receiving execution world is virtualized. It must not introduce or name Hyprvisor. Chapter 32 retains that surprise.

## Evidence design

Every new chapter must classify challengeable claims using the existing evidence vocabulary:

- public documentation;
- direct observation;
- reverse engineering;
- inference;
- dramatization.

Receipts go in a v0.7 receipt file and the fact-check ledger. Chapter prose should remain book-like. It may mention a source naturally when that helps the reader, but repeated phrases such as “from our source, macOS build…” belong in the notes rather than the narrative.

Generation-sensitive material requires special caution:

- Apple-silicon cache topology;
- interrupt routing;
- controller and peripheral firmware responsibilities;
- wake sources and power-domain behavior;
- private driver and I/O pipelines;
- filesystem durability guarantees.

Use primary Apple material where public documentation exists. For open-source implementation details, use primary source code or project documentation. For reverse-engineered Apple-silicon behavior, label the source and the inference. An observed name is not permission to invent semantics.

## Canon and tone

Each chapter should contain at least one dialogue beat that explains the mechanism while landing the joke. A quota does not excuse weak dialogue; the beat must do both jobs.

The strongest comic pattern remains scoped authority:

- a character makes a broad claim;
- another asks for the missing noun;
- the enforcement mechanism answers before the claimant finishes the speech.

Do not repeat the thesis paragraph at every ending. Later chapters should trust the reader and cash earlier concepts as callbacks.

The following exchanges are newly protected in v0.7:

- XNU’s demolition permit;
- XNU asking the SSD to read `/Users/efeali/book.txt`;
- launchd asking firmware for its PID.

All earlier protected canon remains protected, including fake launchd, LaunchAngels, the SEP mailbox, the Civil War evidence note, hardware dinner, shutdown, the ten-core correction, the Larpintosh exchange, and the final `moo.`

## Out of scope

- A deep tutorial on Hypervisor.framework, Virtualization.framework, VMX, or SVM.
- A complete Darwin scheduler, VM, VFS, networking, driver, or power-management reference.
- Private Apple ABI claims inferred from suggestive names.
- Rewriting the established opening or replacing the existing final joke.
- Padding chapters to equal lengths.
- Publishing v1.0. This edition remains a development milestone toward v1.
